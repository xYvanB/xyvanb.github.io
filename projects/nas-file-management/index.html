NAS File Management

Una web app che si appoggia al NAS, in locale o via SMB, e lo rende comodo da usare: navigazione delle cartelle, upload con drag & drop, anteprima di PDF, Word ed Excel nel browser. Ogni utente vede soltanto i file a cui ha accesso, con permessi di lettura, scrittura ed eliminazione per utente o per gruppo, e ogni caricamento conserva la versione precedente del file. Backend Node.js con Express e MySQL, frontend React con Material UI.

La sfida che ho risolto

Il NAS ragiona per cartelle condivise, ma a noi serviva poter nascondere un singolo file dentro una cartella che tutti gli altri vedono. Ho costruito i permessi come una catena: se un file o una cartella ha permessi espliciti valgono solo quelli, altrimenti si risale al genitore, e in fondo alla catena ci sono i permessi di default del gruppo. Ogni elenco di file passa da questo controllo, quindi un file riservato non viene solo bloccato: per chi non ha accesso semplicemente non esiste. Quando si sposta una cartella, i permessi di tutto il suo contenuto la seguono nel nuovo percorso.

Perché è nato

Quando abbiamo dovuto scegliere fra un NAS e il cloud cercavo una via di mezzo, qualcosa che tenesse i file in casa senza rinunciare alla comodità di un servizio online. Il NAS da solo non bastava: la sua interfaccia era lenta e non permetteva di assegnare ruoli precisi né di rendere un file visibile soltanto a certe persone.

Da qui è nato NAS File Management: un’interfaccia web rapida che lavora direttamente sui file del NAS e ci aggiunge quello che mancava, cioè utenti, gruppi e permessi fino al singolo file, più lo storico delle versioni per recuperare in qualsiasi momento una copia precedente di un documento.

Gli screenshot vengono da un’installazione locale con dati di prova: un’azienda immaginaria con le cartelle di Risorse Umane, Amministrazione, Marketing e IT.

Permessi e visibilità

Ogni file e ogni cartella può avere permessi di lettura, scrittura ed eliminazione, assegnati a un singolo utente o a un gruppo. Le cartelle create dall’app copiano i permessi del genitore, e una casella “Eredita dalla cartella superiore” permette di interrompere la catena quando serve. Così la cartella Finance può contenere una nota visibile soltanto al gruppo Amministrazione, anche se il resto della cartella è condiviso più ampiamente.

Gli amministratori vedono tutto; un utente normale vede soltanto ciò che i suoi permessi gli consentono, e le icone R, W e D accanto a ogni voce gli dicono subito cosa può farci. Gli account si possono disattivare senza cancellarli, e i gruppi possono avere anche privilegi amministrativi.

Versioni dei file

Quando si carica un file che esiste già, quello vecchio non viene sovrascritto: finisce in una cartella old version accanto all’originale, direttamente sul NAS, e una copia di backup viene salvata dal server con il suo checksum SHA-256. Ogni versione ha numero, autore, data e un commento facoltativo, e si può scaricare in qualunque momento dalla scheda delle proprietà del file.

Tecnologie usate

Il progetto è un monorepo con backend e frontend separati. Il backend è un’API Node.js con Express, autenticazione JWT, rate limiting e Helmet; utenti, gruppi, permessi e versioni stanno in MySQL tramite Sequelize. Un servizio dedicato astrae lo storage: con una variabile d’ambiente si passa da una cartella locale, comoda per lo sviluppo, al NAS vero raggiunto via SMB. Uno script iniziale scansiona le cartelle esistenti e le cataloga, così l’app parte da quello che c’è già sul NAS.

Il frontend è un’app React 18 con Material UI e React Query: vista a elenco o a griglia, ricerca, breadcrumb, upload multiplo con drag & drop, copia, taglia e incolla anche da tastiera, e un visualizzatore che apre PDF, documenti Word, fogli Excel, immagini e file di testo senza uscire dalla pagina. I test del backend sono scritti con Jest e Supertest.
